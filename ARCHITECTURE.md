# Архитектура первой версии

Приложение состоит из расширения GNOME Shell и отдельного пользовательского
помощника `clipboard-typer-helper`.

* `src/gnome44` — legacy-сборка для GNOME Shell 44 (`imports.*`).
* `src/gnome46` — ESM-сборка для GNOME Shell 45/46.
* `src/helper/clipboard-typer-helper` — читает UTF-8 только из stdin и вводит
  его через XTEST (libX11/libXtst через `ctypes`), без shell, `eval` и внешних
  программ.
* GSettings хранит настройки и, если это разрешено пользователем, не более 20
  уникальных строк истории в пользовательской базе dconf.

Расширение опрашивает текстовый `CLIPBOARD`, дедуплицирует историю, строит меню
панели и регистрирует глобальные сочетания клавиш GNOME Shell. При наборе меню
закрывается, прежнее окно получает фокус, после настраиваемой паузы helper
передаёт ввод активному X11-окну. Остановка посылает helper-у SIGTERM; helper
отпускает нажатые клавиши, восстанавливает раскладку и завершается.

## Выбор клавиш

Helper читает активную XKB-раскладку и для каждого символа ищет физическую
клавишу, группу раскладки и модификаторы (Shift, при наличии AltGr), которые
дают этот символ. Для ASCII предпочитается латинская группа, для остальных
символов — текущая. Поэтому `.` или `;` всегда идут клавишами US-раскладки, и
веб-консоль виртуальной машины, передающая физические клавиши (scan codes),
получает правильные символы. Группа блокируется через `XkbLockGroup` только
когда текущая группа не даёт нужный символ той же клавишей; после ввода
возвращается исходная. Символы, которых нет ни в одной группе, набираются через
свободный keycode, временно назначенный на нужный keysym.

`xdotool type` для этого не подходит: при нескольких раскладках он выбирает
клавиши «чужой» группы (`;` как Shift+4 русской раскладки) и теряет переводы
строк.

Wayland намеренно не поддерживается: XTEST работает только для X11-клиентов,
а ввод через XWayland не является надёжным механизмом для Wayland-приложений.
