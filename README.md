# История буфера и ввод для GNOME 44–48

Расширение GNOME Shell хранит последние 20 уникальных текстов из системного
`CLIPBOARD` и умеет вводить выбранный текст как реальные X11-нажатия клавиш.
Это предназначено, в частности, для веб-консолей виртуальных машин, где обмен
буфером запрещён, а обычная клавиатура работает.

Первая версия поддерживает **только сеанс X11/Xorg**. В Wayland история и
копирование доступны, но кнопка «Напечатать» покажет объяснение и не запустит
ввод.

## Установка готового RPM

Готовые пакеты опубликованы в
[GitHub Releases](https://github.com/polevoimv-debug/gnome-clipboard-typer/releases/tag/v1.0.3).
На РЕД ОС их можно скачать прямо из терминала:

```bash
# GNOME Shell 44
curl -LO https://github.com/polevoimv-debug/gnome-clipboard-typer/releases/download/v1.0.3/gnome-shell-extension-clipboard-typer-gnome44-1.0.3-1.noarch.rpm

# GNOME Shell 45 или 46
curl -LO https://github.com/polevoimv-debug/gnome-clipboard-typer/releases/download/v1.0.3/gnome-shell-extension-clipboard-typer-gnome46-1.0.3-1.noarch.rpm

# GNOME Shell 47 или 48
curl -LO https://github.com/polevoimv-debug/gnome-clipboard-typer/releases/download/v1.0.3/gnome-shell-extension-clipboard-typer-gnome48-1.0.3-1.noarch.rpm

curl -LO https://github.com/polevoimv-debug/gnome-clipboard-typer/releases/download/v1.0.3/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
```

Сначала узнайте версию GNOME:

```bash
gnome-shell --version
```

Затем установите ровно один пакет из каталога `dist`:

```bash
# GNOME Shell 44
sudo -E dnf install ./dist/gnome-shell-extension-clipboard-typer-gnome44-1.0.3-1.noarch.rpm

# GNOME Shell 45 или 46
sudo -E dnf install ./dist/gnome-shell-extension-clipboard-typer-gnome46-1.0.3-1.noarch.rpm

# GNOME Shell 47 или 48
sudo -E dnf install ./dist/gnome-shell-extension-clipboard-typer-gnome48-1.0.3-1.noarch.rpm
```

Пакеты локальной сборки не подписаны GPG. Если политика DNF требует подпись,
сначала сверьте SHA-256 по файлу `dist/SHA256SUMS`, затем используйте для этого
конкретного локального файла:

```bash
cd dist
sha256sum -c SHA256SUMS
sudo -E dnf install --nogpgcheck ./ИМЯ-ПАКЕТА.rpm
```

Пакеты взаимоисключающие. После установки выйдите из GNOME, войдите снова и в
обычном пользовательском терминале выполните:

```bash
clipboard-typer-enable
clipboard-typer-diagnose
```

RPM устанавливает файлы системно, поэтому только установка пакета выполняется с
правами администратора. Само расширение и команда включения от root не
запускаются.

## Исправления 1.0.3

Вместо `xdotool type` используется собственный ввод через X11 XTEST с учётом
раскладок XKB. `xdotool` при раскладках `us,ru` терял переводы строк и для
`;`, `?`, `/` и других знаков нажимал клавиши русской раскладки: веб-консоль
виртуальной машины, которая передаёт физические клавиши, получала `$`, `&`, `|`.
Теперь:

* латиница, цифры и знаки препинания набираются клавишами латинской раскладки,
  кириллица — клавишами русской, раскладка на время символа переключается и
  после ввода возвращается исходная;
* перевод строки (LF, CRLF, CR) — одно нажатие Enter, табуляция — Tab;
* неразрывные и прочие «широкие» пробелы из веб-страниц печатаются обычным
  пробелом, невидимые управляющие символы пропускаются;
* включённый Caps Lock на время ввода выключается и затем восстанавливается;
* символы, которых нет ни в одной раскладке (`✓`, `—`), набираются через
  временно назначенную свободную клавишу; в веб-консоли ВМ они, как и раньше,
  могут не появиться;
* остановка отпускает нажатые клавиши и восстанавливает раскладку.

## Исправления 1.0.2

Зарегистрированы GObject-классы индикатора и диалогов, исправлена связь
подменю истории с основным меню. Ввод многострочного текста начинается после
закрытия диалога и освобождения фокуса. После обновления выйдите из GNOME и
войдите снова: выключение и включение расширения не перечитывает его модули.

Если общий переключатель расширений выключен, включите его в приложении
«Расширения». Проверка: `gsettings get org.gnome.shell disable-user-extensions`.
Значение `true` блокирует запуск даже включённого расширения.

## Требования

* РЕД ОС с GNOME Shell 44–48;
* сеанс «GNOME on Xorg» для функции набора;
* `python3`, библиотеки `libX11` и `libXtst` (желательно `libxkbcommon`),
  `glib-compile-schemas`, `gnome-extensions`;
* запуск приложения обычным пользователем.

Проверка до установки:

```bash
./diagnose.sh
```

Если зависимостей нет, сначала найдите их в подключённых репозиториях:

```bash
dnf info libX11 libXtst libxkbcommon python3 glib2 gnome-shell
sudo -E dnf install libX11 libXtst libxkbcommon python3 glib2 gnome-shell
```

Названия пакетов следует подтвердить через `dnf info` именно на целевом
компьютере. РЕД ОС официально использует DNF, но состав подключённых
репозиториев может отличаться. Не подключайте репозитории другой ОС ради
недостающих библиотек: это может нарушить совместимость системы. Документация:
[управление RPM/DNF в РЕД ОС](https://redos.red-soft.ru/base/faq/faq-rpm-dnf/) и
[источники программ](https://redos.red-soft.ru/base/redos-8_0/8_0-base-consept/8_0-sys-dnf/8_0-gen-info-dnf/8_0-dnf-repo/).

## Установка

```bash
chmod +x install.sh uninstall.sh diagnose.sh
./install.sh
```

Установщик:

1. определяет версию `gnome-shell`;
2. выбирает legacy-сборку для GNOME 44 или ESM-сборку для 45–48;
3. устанавливает файлы только в
   `~/.local/share/gnome-shell/extensions/clipboard-typer@local`;
4. компилирует локальную схему GSettings и пытается включить расширение.

Если GNOME ещё не видит новое расширение, выйдите из графического сеанса,
войдите снова и выполните:

```bash
gnome-extensions enable clipboard-typer@local
```

Включённое расширение автоматически запускается при следующих входах в GNOME;
отдельный root-сервис или стороннее расширение трея не нужны.

## Использование

1. Скопируйте текст обычным способом. Через доли секунды он появится под
   значком буфера в верхней панели.
2. Нажмите запись: доступны полный просмотр, «Скопировать» и «Напечатать».
3. Для ввода сначала поставьте курсор в Chrome/веб-консоль. После выбора
   «Напечатать» прежнее окно получает фокус, затем действует пауза 2 секунды.
   За это время можно вручную выбрать нужное поле.
4. Если есть переносы строк, расширение каждый раз спрашивает: сохранить их или
   заменить пробелами. Сохранённый перенос — это Enter и в терминале может
   выполнить команду.

Во время ввода значок меняется на клавиатуру. Второй ввод одновременно не
запускается.

Сочетания клавиш:

* `Super+V` — открыть/закрыть историю;
* `Super+Shift+Esc` — немедленно остановить ввод.

Оба сочетания зарегистрированы GNOME Shell глобально и поглощаются оболочкой,
поэтому не должны попадать в целевое окно. Если сочетание занято, его можно
изменить, например:

```bash
gsettings --schemadir "$HOME/.local/share/gnome-shell/extensions/clipboard-typer@local/schemas" \
  set org.gnome.shell.extensions.clipboard-typer open-history "['<Super><Alt>v']"
```

Настройки в меню позволяют менять паузу перед началом, интервал между символами,
приостанавливать сбор и выключать хранение на диске. При выключении дискового
хранения уже сохранённая история немедленно удаляется из dconf, но остаётся в
оперативной памяти до очистки или завершения сеанса расширения. «Очистить
историю» удаляет и память, и сохранённое значение.

## Конфиденциальность и безопасность

История хранится в пользовательской базе dconf, доступной в контексте текущего
пользователя. В ней не более 20 непустых уникальных строк; повторное копирование
поднимает строку наверх. Текст не пишется в журналы.

Helper читает UTF-8 через stdin и сам отправляет нажатия через libXtst, без
внешних программ. Текст не становится shell-командой, не подставляется в
командную строку, `eval`, `subprocess` и `shell=True` не используются. При
остановке helper отпускает нажатые клавиши, возвращает раскладку, Caps Lock и
временно назначенную клавишу.

## Удаление

```bash
./uninstall.sh
```

Удаляется пользовательская копия расширения, история и настройки dconf. Это
необратимая очистка. Системные пакеты не удаляются.

## Диагностика

```bash
./diagnose.sh
gnome-extensions info clipboard-typer@local
journalctl --user -b --no-pager | grep -F 'clipboard-typer@local'
```

Диагностика не читает и не выводит буфер. Типичные причины:

* `XDG_SESSION_TYPE=wayland` — на экране входа выберите «GNOME on Xorg»;
* `FAIL libXtst.so.6` — установите `libXtst` из доверенного репозитория РЕД ОС;
* значка нет после установки — перелогиньтесь и включите расширение;
* неверные символы — проверьте активную XKB-раскладку и тест ниже.

Ввод использует расширение X11 XTEST, поэтому работает только в сеансе Xorg:
в Wayland такие события не доходят до обычных приложений.

## Ручная проверка на целевом GNOME

Проверяйте по порядку, каждый раз останавливаясь при ошибке:

1. **Обычное поле.** Откройте Text Editor, скопируйте и напечатайте:
   `English Русский 123 !@# № — ✓`, затем многострочный текст. Проверьте оба
   варианта обработки переносов и остановку посередине длинной строки.
2. **Chrome.** Повторите в адресной строке и в обычном поле веб-страницы.
   Проверьте, что окно снова получает фокус после закрытия меню.
3. **Веб-консоль ВМ.** Сначала используйте безопасное пустое текстовое поле, не
   терминал. Проверьте английский, кириллицу, цифры, кавычки, обратный слеш,
   `@`, `№`, `—`, переносы. Затем отдельно проверьте терминал с заменой переносов
   пробелами.
4. Во время длинного ввода нажмите `Super+Shift+Esc` и убедитесь, что новые
   символы сразу перестали поступать.
5. Перезайдите в GNOME: история должна восстановиться только при включённом
   хранении на диске.

Системная имитация клавиатуры не гарантирует работу во всякой веб-консоли.
Chrome, конкретный JavaScript/Canvas-клиент, XKB-раскладка и обработка Unicode в
удалённой консоли могут менять результат. Особенно важно проверить кириллицу и
символы, которых нет в текущей раскладке. Локально в среде разработки можно
проверить логику и безопасность, но совместимость считается подтверждённой
только после этого теста на целевой РЕД ОС.

## Тесты разработчика

```bash
python3 -m unittest discover -s tests -v
node tests/test_extension_runtime.cjs
glib-compile-schemas --strict src/schemas
node --check src/gnome44/extension.js
node --check src/gnome46/extension.js
```

Сборка двух RPM на РЕД ОС/Fedora-подобной системе:

```bash
sudo -E dnf install rpm-build glib2
./build-rpm.sh
```

Переход GNOME 45 на ESM описан в официальном
[руководстве GNOME](https://gjs.guide/extensions/upgrading/gnome-shell-45.html),
поэтому проект содержит две сборки, а не заявляет непроверенную универсальность
одного файла.
